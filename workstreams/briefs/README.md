# 📋 Brief Workspaces

Each brief keeps its requirements, concepts, notes, exercises, feedback, and deliverables together.

## 🧭 Learning workflow

For every new brief:

1. Analyze the full brief and inspect the existing project baseline.
2. Separate confirmed requirements from assumptions and optional work.
3. Order the required concepts by dependency and risk.
4. Attach one learner exercise and one completion check to every concept.
5. Work through one concept at a time and create its detailed lesson only when study begins.
6. Mark a concept complete only after the exercise, behavior, and learner explanation are verified.

Delivery requirements such as Jira, pull requests, documentation, and Docker remain visible, but they do not replace the JavaScript learning concepts.

## Standard structure

```text
brief-name/
├── README.md      # Scope, status, and next step
├── concepts/      # Technical concepts used in the brief
├── notes/         # Decisions and explanations
├── exercises/     # Practice connected to feedback
├── feedback/      # Mentor or reviewer evaluations
└── deliverables/  # Verified outputs
```
